# Журнал взаємодії із ШІ (лабораторна №5)


## Інструмент
ChatGPT — для аналізу вимог, планування архітектури, підготовки коду та перевірки логіки.

## Початковий промпт
«На основі мого  сайту з лабораторної роботи 4 розроби повноцінний навчальний вебзастосунок. Збережи наявні HTML-сторінки, CSS та зображення. Додай сервер Node.js та Express, базу SQLite, REST API з CRUD для товарів, створення й перегляд замовлень. Підключи клієнт до API через Fetch та async/await. Кошик має працювати, а оформлення замовлення повинно зберігатися в базі. Перевіряй введені дані на сервері, використовуй параметризовані SQL-запити, обробляй помилки. Підготуй README з інструкцією запуску».

## Уточнювальні промпти
1. «Перевір структуру таблиць і зв’язки між товарами, замовленнями та позиціями замовлення».
2. «Перевір серверну валідацію, параметризовані запити та обробку помилок».
3. «Підключи кошик до REST API так, щоб сервер сам визначав актуальні ціни товарів під час оформлення замовлення».
4. «Підготуй інструкцію запуску, тестові маршрути API та перелік обмежень безпеки».

## Результат і перевірка людиною
ШІ підготував структуру Node.js/Express, схему SQLite, REST-маршрути, клієнтський Fetch-код і документацію. Рішення перевіряється запуском сервера, переглядом `/api/health`, `/api/products`, оформленням тестового замовлення та перевіркою записів через `/api/orders`. Помилки запуску або тестування потрібно записати тут після фактичної перевірки.

## Внесені зміни
- Замість переходу з кнопки «Додати до кошика» на порожню сторінку реалізовано збереження кошика в localStorage.
- Замість демонстраційного повідомлення про замовлення реалізовано POST `/api/orders`.
- Вартість замовлення повторно обчислюється сервером за даними SQLite.
- Додано серверну валідацію, параметризовані SQL-запити та базові HTTP-заголовки безпеки через Helmet.

## Додатковий етап: особистий кабінет і авторизація

**Промпт:** «Додай до сайту власний кабінет користувача з реєстрацією, входом та списком його замовлень. Використай Node.js, Express і SQLite. Паролі не зберігай у відкритому вигляді; зв'яжи замовлення з ID користувача; користувач має бачити тільки власні замовлення. Додай клієнтські сторінки авторизації та кабінету й інтегруй їх з існуючим кошиком».

**Реалізовано:** таблицю users; поле user_id у orders з міграцією старої бази; bcrypt-хешування паролів; JWT авторизацію; API реєстрації, входу, профілю та особистих замовлень; сторінки auth.html і account.html; перенаправлення неавторизованого користувача перед оформленням замовлення.

**Перевірка розробником:** потрібно виконати локальний запуск, створити тестовий акаунт, увійти, оформити тестове замовлення та перевірити його появу у кабінеті. Окремо перевірити, що інший акаунт не бачить це замовлення.
