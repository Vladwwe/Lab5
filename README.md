# TECH STORE — лабораторна робота №5

Навчальний вебзастосунок магазину техніки на основі клієнтської частини з лабораторних №1–4. Додано сервер Node.js + Express, REST API та базу SQLite.

## Запуск локально

1. Встановити Node.js 20 або новіший.
2. Відкрити термінал у папці проєкту.
3. Виконати `npm install`.
4. Виконати `npm start`.
5. Відкрити у браузері `http://localhost:3000/main.html`.

База `data/tech-store.sqlite` створюється автоматично під час першого запуску. Три початкові товари додаються автоматично.

## Архітектура

- `public/` — клієнтська частина HTML/CSS/JS та зображення.
- `server.js` — сервер Express, REST API, перевірка даних та обробка помилок.
- `src/database.js` — створення SQLite бази, таблиць і початкових товарів.
- `data/` — файл бази даних (створюється автоматично; не потрібно завантажувати в GitHub).

Клієнт звертається до сервера через Fetch API. Кошик зберігається у localStorage браузера, а оформлені замовлення — у SQLite. Ціна для замовлення повторно береться з бази даних на сервері, а не довіряється браузеру.

## REST API

| Метод | Маршрут | Призначення | CRUD |
|---|---|---|---|
| GET | `/api/health` | Перевірка доступності сервера | — |
| GET | `/api/products` | Список товарів | Read |
| GET | `/api/products/:id` | Один товар | Read |
| POST | `/api/products` | Створити товар (для демонстрації) | Create |
| PUT | `/api/products/:id` | Оновити товар | Update |
| DELETE | `/api/products/:id` | Видалити товар | Delete |
| POST | `/api/orders` | Створити замовлення та позиції | Create |
| GET | `/api/orders` | Переглянути замовлення (навчальний маршрут) | Read |

## Модель даних

- `products`: id, name, description, price, image.
- `orders`: id, customer_name, phone, address, total, created_at.
- `order_items`: id, order_id, product_id, product_name, quantity, unit_price.

Зв’язок: одне замовлення має багато позицій; позиція посилається на товар. Назва й ціна товару також зберігаються в позиції замовлення як історичний знімок.

## Перевірка API

Після запуску відкрийте `http://localhost:3000/api/health` і `http://localhost:3000/api/products`. Для створення тестового замовлення можна використати форму на сторінці кошика. Для перевірки CRUD POST/PUT/DELETE можна використати Postman або Thunder Client.

Приклад JSON для POST `/api/products`:

```json
{ "name": "USB-накопичувач", "description": "Тестовий товар", "price": 299, "image": "photo1.jpg" }
```

## Безпека та обмеження

Використано Helmet, обмеження розміру JSON, параметризовані SQL-запити, серверну перевірку полів і телефонного номера, обробку 404/500. У проєкті немає авторизації адміністратора, платіжної системи та захисту від автоматизованого спаму — це навчальний прототип, не готовий комерційний магазин. Для публічного розгортання потрібно додатково налаштувати HTTPS, резервні копії, rate limiting та секрети через змінні середовища.

Проєкт можна розгорнути на Render або іншій платформі, що підтримує Node.js. Вкажіть Build Command `npm install`, Start Command `npm start`, Node.js 20+. ## Особистий кабінет, реєстрація та історія замовлень

У проєкті додано:
- реєстрацію за ім'ям, електронною поштою та паролем (`/api/auth/register`);
- вхід за електронною поштою та паролем (`/api/auth/login`);
- перевірку поточного користувача (`/api/auth/me`);
- сторінку `auth.html` для входу та реєстрації;
- сторінку `account.html` з профілем та особистою історією замовлень;
- прив'язку кожного нового замовлення до авторизованого користувача;
- захист перегляду історії: користувач бачить лише власні замовлення.

Паролі хешуються бібліотекою bcryptjs, а авторизація працює через JWT-токен. Токен зберігається в localStorage браузера і надсилається серверу в заголовку Authorization. Замовлення без входу не оформлюється: користувача перенаправляє на сторінку авторизації.

### Запуск після оновлення

```bash
npm install
npm start
```

Відкрити `http://localhost:3000/main.html`. Для реєстрації перейти за посиланням «Увійти» у меню, перемкнутися на «Реєстрація», заповнити форму. Після входу в меню з'явиться «Мій кабінет».

### Налаштування секретного ключа перед публікацією

Для локальної демонстрації використовується тестовий ключ. Перед розгортанням на хостингу обов'язково встановіть власний довгий випадковий `JWT_SECRET` у змінних середовища платформи. Не додавайте секрет до GitHub. Також використовуйте HTTPS на опублікованому сайті.

Примітка: старі замовлення, створені до додавання реєстрації, залишаються в базі, але не належать жодному користувачу. У кабінеті відображаються нові замовлення, оформлені після входу.
